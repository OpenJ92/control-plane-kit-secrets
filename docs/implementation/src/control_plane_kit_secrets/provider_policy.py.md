This module owns the exact provider-policy v2 schema, one-time bootstrap seed transformation and durable runtime grant authority. It does not authenticate requests; [api.py](../../../../src/control_plane_kit_secrets/api.py) authenticates first and supplies the authenticated subject and correlation.

The seed input is an explicit tuple of already parsed ProviderCredential values. Tokens are never stored or hashed. Credentials sharing a subject must normalize to the same exact grant set, including empty sets, before empty subjects are omitted. Seed tuples reject wildcard workspace/action/intent, unknown actions, unsupported intents and intentless actions with nonempty intent lists. The provider-bound canonical digest covers only sorted exact subject/workspace/action/intent tuples.

All schema creation, seed rows/events, singleton marker and initial revision use the caller-owned custody transaction. Seed grant identities are deterministic from provider and exact tuple. Seed events require that real grant and its exact coordinates. Grant and revoke commands serialize in SQLite, compare the expected revision, append their event and command result, and advance the provider revision once in one transaction. An exact correlation replay returns the original canonical nonsecret result without writes; changed reuse appends a bounded conflict event without replacing that result. Regrant after revocation creates a new UUID identity. Event failure rolls back mutation and command result.

Authorization requires one active exact tuple. Reads of one grant, current filtered pages and command results use the same SQLite transaction as their required event append; event failure returns no data. Cursor pagination is bounded and current-state only. Grantless denial/conflict/invalid events retain authenticated actor and correlation while omitting nonexistent grant coordinates. No token or secret material enters the policy store.

Restart verification reconstructs the digest from every immutable seed-origin tuple, including revoked rows, and excludes later command-origin grants and mutable revocation fields. This is internal consistency evidence, not cryptographic protection from an actor able to rewrite both rows and marker coherently. Exact schema/provider/master-key admission remains in [custody.py](../../../../src/control_plane_kit_secrets/custody.py).
