admit_provider_custody binds one retained SQLite store to the supplied provider identity, master key and exact declared schema before returning secret/audit stores. It owns the single recognized v1-to-v2 provider-policy transition, not a generic migration engine, CPK graph ownership or automatic recovery.

SQLite's BEGIN IMMEDIATE serializes the admission transaction. An object-free database requires an explicit policy seed input and receives secret/audit/policy/binding schema, the one-time seed and an authenticated v2 witness together. Exact bound v1 is verified before any DDL, then policy objects and seed are committed with the v2 witness while existing custody rows remain untouched. Missing seed is distinct from explicit empty seed. Exact v2 restart verifies its stored seed-origin provenance without consulting current credential grants. Failure rolls back logical changes. Existing unbound, partial, extra or incompatible stores are rejected, not adopted or repaired.

Contract-bearing dependencies are [EncryptedSecretStore's schema and transaction initializer](../../../../src/control_plane_kit_secrets/store.py), [SqliteAuditStore's schema and transaction initializer](../../../../src/control_plane_kit_secrets/audit.py), [provider policy schema/seed](../../../../src/control_plane_kit_secrets/provider_policy.py) and [MasterKey](../../../../src/control_plane_kit_secrets/crypto.py). Changing an owned schema changes admission compatibility even when this file is untouched. A corresponding data decision is required; documentation cannot turn drift into an approved migration.

Fixed rejected/unavailable categories distinguish incompatible custody from operational inability to establish it. SQLite still owns its own locking/recovery. Logical-state preservation is not byte-identical filesystem preservation: the function may create parent directories and SQLite may manage journals. Path checks do not claim protection from hostile path replacement.

The custody tests in [test_encrypted_store.py](../../../../tests/test_encrypted_store.py) cover explicit seed admission, empty/populated restart, exact v1 migration, rollback, seed-once/no-resurrection, wrong provider/key, tampered binding, unbound/changed schema and concurrency. These are local custody laws, not a retained live migration, provider readiness or capstone acceptance. [AGENTS.md](../../../../AGENTS.md) retains the governing authority limits.
